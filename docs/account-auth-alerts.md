# OAuth 授权失败飞书通知

## 当前部署（2026-11-15）

本机已安装 `com.toooa.sub2api.account-auth-alerts` LaunchAgent，每 300 秒执行一次 Python 标准库脚本。巡检只读纽约与武汉的 OpenAI OAuth 账号运行错误及使用记录，不查询模型推理接口、不修改账号或调度，也不消耗额度重置机会。正常巡检不发送消息；授权告警通过用户已授权的 `feishu-ask notify` 机器人发给本人。

源码及安装说明：[tools/account-auth-alerts/README.md](../tools/account-auth-alerts/README.md)。运行副本在外置盘项目的 `tools/account-auth-alerts/`；配置和去重状态在 `private/account-auth-alerts/`。没有向本地返回访问令牌或刷新令牌；上游错误正文在服务器内归约为预定义错误标记后才传回。

## 告警范围与标注

按上游账号 ID 合并两站重复记录。默认只提醒以下任一条件成立的账号：近 7 天有成功调用、当前仍配置参与调度、近 7 天曾被巡检观察为健康且参与调度。授权失败可自动停用账号，因此不单凭 `schedulable=false` 排除近期在用号。私人 `ignored_accounts` 列表可按邮箱或上游 ID 永久忽略用户明确不再使用的账号。

每条告警包含邮箱、站点与账号 ID、登记套餐、当前调度状态、各站最后成功调用时间、各站近 7 天成功调用次数和归一化错误原因。登记套餐可能过时；已停用不等于用户主动弃用；没有保留的成功日志也不等于从未用过。未接入中转站的本地备用号、API Key 账号、已删除账号不在本监控范围。

首次验收曾把 14 个已有授权错误汇总发送。用户要求区分历史账号后，核对两站真实用量记录，当前仅 4 个异常身份在近 7 天成功调用过；其他 10 个已停用且无近期成功调用，已不再主动提醒其旧错误。已通过同一飞书话题补发逐号标注；原有去重状态保留，没有重新群发相同授权告警。

## 防重复与故障边界

- 两次授权错误观察、首次到确认至少 5 分钟，才触发告警；一般约 5–10 分钟，睡眠、网络和调度延迟可能延长。
- 同一事件只通知一次；两次完整健康观察且间隔至少 5 分钟后重新布防。站点不可达不能当作账号恢复。
- 401、撤销令牌、刷新令牌重用等属于授权错误；单纯令牌到期时间、403、额度耗尽、网络失败不作授权失败证据。
- 站点连续三次、跨至少 10 分钟无法检查，发单独的“监控不可用”通知，账号状态标为未知。
- 发送失败保留待发事件，下轮重试；状态原子保存，OS 文件锁避免并行重复。损坏状态停止执行，不自动清空。消息送达后、本地状态写入前崩溃仍可能在重试时重复一次。
- 告警依据服务器已记录错误，不代表每轮重新访问上游证明凭据失效；重新授权后仍保留旧错误的账号需要核对并恢复运行状态。

## 运行依赖与验证

Mac 需开机、登录并保持外置盘及 SSH/飞书网络可用；五分钟巡检不需要 Codex 开着，也不消耗模型会话。仅必需的 LaunchAgent plist、启动 wrapper 与约 1 MiB 上限启动日志放在用户 Library。额外创建了 Codex `automation-8`，每天北京时间 09:05 检查 LaunchAgent 并运行一次同样去重的脚本；该补充检查依赖 Codex 正常运行。

21 项自动测试通过，覆盖授权与非授权错误区分、两站合并、历史账号过滤、显式忽略、近期使用后自动停用、先前健康调度记忆、告警标注、去重、恢复重新布防、部分站点失联、发送重试、损坏状态及秘密错误正文剥离。真实巡检读回纽约 17 条、武汉 24 条 OAuth 记录；真实飞书发送成功，后台再次执行零新增消息，最近退出码 0、周期 300 秒。SQL 使用已有 `(account_id, created_at)` 索引及 20 秒语句超时。

本机证据和备份在项目 `outputs/2026-11-14-account-auth-alerts/`：修改前运维文档、首次发送结果、逐号使用标注、范围修正前脚本/配置/状态，以及被替换的启动脚本、plist、运行副本与 README。私人配置和状态不提交 Git。回滚应保留去重状态，使用安装备份恢复对应运行文件并重新加载 LaunchAgent。

旧 `account-pro-alerts` 日任务有独立的账号范围和续费规则，本次未改其策略；其安装 wrapper 仍指向已退役洛杉矶，不能作为当前授权告警的有效覆盖。本功能使用独立任务、配置、状态和当前两站地址。
